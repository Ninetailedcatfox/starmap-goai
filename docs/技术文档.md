# 技术文档

## 多 Agent 协同机制

本项目通过单次 LLM 调用内嵌四段式角色分工，模拟多 Agent 协同：洞察 → 情报 → 匹配 → 可视化。一次推理产出完整 JSON 结果（RIASEC 画像 + 战略方向 + 职业路径 + 时间轴）。

### 后端结构

```
前端 index.html ──POST /api/analyze──→ 后端 server.py
                                          │
                                          ├─ 组装 SYSTEM_PROMPT（含 RIASEC 评分规则 + 匹配规则）
                                          ├─ 调 LLM（OpenAI 兼容 API，默认 gpt-5.5）
                                          ├─ 解析 JSON（剥离 ``` 代码块）
                                          └─ 返回前端渲染
```

### 四段式职责（单次调用内完成）

| 阶段 | 对应 Agent | 职责 |
|---|---|---|
| 洞察 | ① 画像 Agent | 依选科/兴趣/自述打 RIASEC 六维分数 + 人格摘要 + 能力标签 |
| 情报 | ② 情报 Agent | 依 RIASEC 生成匹配的前沿方向，每条配国家战略意义 + 院校梯度 |
| 匹配 | ③ 匹配 Agent | 输出 3-5 个职业路径，配匹配度/薪资/趋势/院校 |
| 可视化 | ④ 可视化 Agent | 输出 4 段人生时间轴（高中/本科/深造/成熟期） |

### 匹配规则（关键设计）

1. 先打 RIASEC 六维分数，再据此匹配方向——不是反过来。
2. A/S 主导 → 人文社科前沿（文化遗产数字化、科技考古、AI 伦理等）。
3. I/R 主导 → 理工前沿（粒子物理、航天、聚变、量子、AI 芯片等）。
4. 方向从模型知识自由生成、不限个数，但必须真实、前沿、有国家战略背景。
5. 约束：A/S 型学生 top 方向不得出现粒子物理/航天/聚变。

### 数据合规与隐私

- 学生信息仅在请求内存中处理，服务端不落盘、不持久化。
- 心理测评结果为即时生成，不存储原始回答。
- 战略方向信息来自 LLM 训练数据，参照公开科技公告，未接入实时数据库。
- 不收集、不传输任何可关联到个人的敏感数据。
